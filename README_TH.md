- หลังคลีน กด **เพิ่ม Text / รับคำแปล → จัด Text จากคำแปลที่มีในโปรแกรม** ข้อความจะพอดีกับพื้นที่ปลอดภัยในแนวเอียงและจัดกลางกรอบ ทั้งภาพแสดงผลและ PSD ใช้มุมเดียวกัน Text ใน Photoshop ยังแก้ไขได้ คง TH Sarabun New Bold / Auto / Tracking 0 / Metrics / Sharp และสีขาวหรือดำตามพื้นหลัง
- งานเก่าไม่เปลี่ยนกรอบหรือคำแปลเองตอนเปิด หากมีกรอบเอียงเดิมอยู่แล้ว ให้จัด Text ใหม่เพื่อเพิ่มมุมให้ชั้นข้อความ หากมีแต่กรอบตรง ต้องอ่าน OCR ใหม่หรือปรับมุมเองก่อน (บันทึกสำเนาโปรเจกต์ก่อนอ่านใหม่ เพราะ OCR ใหม่แทนรายการกรอบ)
- เปิดภาพหรือเปลี่ยนหน้าเริ่มที่ **56%** กด **ซูม 56%** เพื่อกลับค่าตั้งต้น มีปุ่ม − / + และพอดีความกว้างเหมือนเดิม ภาพยังจัดกลางและพื้นที่ภาพ/เครื่องมือยังเป็น 70/30
- การเอียง Text เป็นการหมุนในระนาบ ไม่ใช่การบิดตัวอักษรตามภาพแบบ perspective; การปรับมุมไม่ได้รับประกันว่า OCR จะอ่านถูกหรือคลีนสะอาดทุกกรอบ ต้องตรวจ Mask ก่อน Clean เช่นเดิม

## มุมมองภาพใหม่ — พื้นที่ 70/30 และภาพกึ่งกลาง

- แบ่งพื้นที่ทำงานเป็นภาพประมาณ **70%** และชุดตรวจ/แก้ไข **30%** สำหรับจอ 1920×1080 ลากเส้นแบ่งแนวตั้งเพื่อปรับได้ ดับเบิลคลิกเส้นแบ่งเพื่อคืน 70/30; หน้าต่างเล็กจะรักษาความกว้างขั้นต่ำของส่วนควบคุมเพื่อให้ใช้งานได้
- เปิดหน้าแล้วใช้ซูม **56%** จัดกลางแนวนอน ภาพสั้นจัดกลางแนวตั้งด้วย ส่วนหน้าการ์ตูนยาวเริ่มด้านบนและเลื่อนขึ้นลงได้ หากภาพกว้างเกินพื้นที่เลื่อนได้ทั้งสองแนว
- ปุ่ม **− / +** และ Ctrl+ล้อเมาส์ยังซูมได้ พร้อมตัวเลขเปอร์เซ็นต์ ซูมโดยรักษาตำแหน่งกลางที่กำลังดู; **พอดีความกว้าง** ขยายภาพตามพื้นที่ และ **ซูม 56%** คืนขนาดเริ่มต้น
- การจัดกลางเป็นการเปลี่ยนมุมมองเท่านั้น พิกัดกรอบ มาสก์ ภาพต้นฉบับ และ PSD ยังใช้ขนาดเดิม ปุ่มอ่านกรอบซ้ำในแผงขวาจะเรียงลงเมื่อพื้นที่แคบ

## อัปเดต 13 ตุลาคม 2026 — กรอบเอียง / จัดบรรทัดมังฮวา / RTX 4060

เปิด `START_3_1.bat` หลังปิดโปรแกรมเดิม อัปเดตไฟล์ทั้งชุด รวม `frame_geometry.py` ด้วย

- **กรอบเอียง:** เลือกกรอบ → เปิด **ปรับกรอบเอียง** → ลากจุดมุมทั้ง 4 หรือกด **หมุนกรอบ…** แล้วอ่านคำซ้ำ ภาพที่ส่ง OCR จะถูกปรับให้ตรงเฉพาะกรอบนั้น พิกัดคำจะถูกแปลงกลับไปยังภาพเดิม กรอบไขว้หรือออกนอกภาพจะไม่ถูกนำไปใช้
- การเปลี่ยนมุมเก็บรหัส ต้นฉบับ และคำแปลไว้ แต่ล้างตำแหน่ง OCR/มาสก์ร่าง/Text layout ที่ไม่ตรงกับกรอบใหม่ จึงต้อง **สร้าง Mask → ตรวจ Mask → Clean → จัด Text ใหม่** ผลคลีนเก่ายังอยู่จนมีผลใหม่และย้อนกลับด้วย Undo ได้ บันทึกโปรเจกต์เก็บมุมที่ปรับไว้ด้วย
- **คำสั้นและเครื่องหมาย:** แยกกรอบ OCR ที่อ่านเส้นบับเบิ้ลทั้งวงเป็นเครื่องหมายออกจากพิกัดตัวอักษร และยังตรวจจุด/เศษเส้นจากภาพ ไม่ละเลยคำความมั่นใจต่ำ การคลีนคำเอียงใช้มาสก์ตามรูปหลายเหลี่ยมและตัวอย่างสีที่เหมาะกับกรอบเล็กขึ้น
- **Text แบบมังงะ/มังฮวา:** จัดกลางบับเบิ้ลทั้งแนวนอนและแนวตั้ง เลือกตัดคำให้ 2 บรรทัดมีบรรทัดล่างยาวกว่าเล็กน้อย หรือ 3 บรรทัดมีบรรทัดกลางยาวกว่า ใช้พื้นที่ปลอดภัยหลายสัดส่วนร่วมกับขนาดตัวอักษร ลดจากขนาดใหญ่ที่สุดที่วางได้ไม่เกิน 20% เพื่อหาจุดตัดคำที่เหมาะสม ไม่บังคับรูปทรงจนเกิดบรรทัดสั้นโดดหรือทำคำหาย หากคำแปลมีการขึ้นบรรทัดเองจะรักษาไว้ ข้อความที่ยาวเกินพื้นที่ยังต้องย่อหรือปรับกรอบ
- คง TH Sarabun New Bold, Auto leading 120%, Tracking 0, Metrics, Sharp และสีขาวบนพื้นมืด/ดำบนพื้นสว่าง Text ใน PSD ยังแก้ไขได้ ใช้ **เพิ่ม Text / รับคำแปล → จัด Text จากคำแปลที่มีในโปรแกรม** เพื่อจัดงานเก่าใหม่ ดูตัวอย่างที่ `examples/v3_1/manga_typesetting.png`
- **ชื่อ PSD:** ใช้เลขท้ายชื่อภาพ เช่น `67_1.png` → `01.psd`, `01_4.png` → `04.psd`; ชื่อที่ไม่มีเลขท้ายใช้ลำดับหน้าในโปรเจกต์ หากมีไฟล์ชื่อนั้นอยู่แล้วจะเป็น `04_1.psd` เพื่อไม่ทับงานเดิม ส่งออกเฉพาะ PSD ตามเดิม

### เร่ง CLEAN ด้วย RTX 4060 โดยรักษาขั้นตอนตรวจ

เครื่องที่ใช้พัฒนารอบนี้ติดตั้งและทดสอบ PyTorch `2.6.0+cu124` กับ RTX 4060 8 GB แล้ว LaMa เลือก CUDA อัตโนมัติ เปิด **เมนูเพิ่มเติม → ตรวจ LaMa** เพื่อดูความพร้อม เครื่องนี้ไม่ต้องติดตั้งซ้ำ

สำหรับติดตั้งใหม่: ปิดโปรแกรม → รัน `install_gpu_windows.bat` หลังติดตั้งโปรแกรมและโมเดล LaMa แล้ว → เปิด `START_3_1.bat` ใช้รุ่น PyTorch/torchvision เดิมแต่เปลี่ยนเป็นชุด CUDA ตาม [คำสั่งทางการ PyTorch](https://pytorch.org/get-started/previous-versions/) ต้องมีไดรเวอร์ NVIDIA ที่รองรับ หากต้องการกลับ CPU ใช้ `restore_cpu_windows.bat` ชุด ZIP ไม่รวม `.venv` หรือโมเดล

ไม่ได้ลดความละเอียด ลดความแม่นยำเลขคำนวณ หรือลดรอบ OCR/ตรวจคลีน ผล CPU/GPU อาจต่างระดับพิกเซลเล็กน้อยตามการคำนวณ ช่วง LaMa ของ 3 กรอบทดสอบเร็วขึ้นประมาณ 2.1–13.7 เท่า **ไม่ใช่อัตราเร่งของงานทั้งหน้า** การอ่านคำ ตรวจเศษเส้น พื้นสีล้วน/ไล่สี และส่งออก PSD ยังมีเวลาเดิม หากหน่วยความจำ GPU เต็มจะลองโมเดลเดิมบน CPU ที่ความละเอียดเดิม พร้อมบันทึกสาเหตุ ไม่ใช้ Telea แทนอัตโนมัติ

ข้อจำกัดจากภาพจริง: กรอบ `Y...` ที่ให้ทดสอบผ่าน OCR และตรวจเศษเส้นแล้ว แต่ข้อความเล็กเอียงบนหน้าจอโทรศัพท์บางกรอบยังมีเศษตัวอักษร/พื้นซ่อมไม่เรียบ ต้องตรวจและแก้มาสก์หรือเลือกวิธีคลีนเอง ผลที่ขึ้น **ต้องตรวจเพิ่ม** ยังไม่ใช่งานที่ผ่านคุณภาพ รายละเอียดและจำนวนจริงอยู่ใน `TEST_REPORT.md`

- ปุ่มเมนูมุมมน พร้อมเงาใต้ปุ่ม แสงเรืองตามสีของกลุ่ม และแสงเมื่อชี้เมาส์/โฟกัส คงธีมเกม ตำแหน่งปุ่ม คีย์บอร์ด และเสียงไม่เกิน 15%
- Text หาศูนย์กลางจากพื้นที่ด้านในบับเบิ้ล ลดอิทธิพลของหางและกรอบ OCR ที่เยื้อง ทดลองพื้นที่กว้าง/สูงหลายแบบก่อนเลือกขนาดและตัดบรรทัด ไม่อนุญาตให้ล้นกรอบ ข้อความนอกบับเบิ้ลที่เป็นกรอบยาวใช้พื้นที่สี่เหลี่ยมแทนการหดเป็นวงรี
- **สีขาวบนพื้นมืด สีดำบนพื้นสว่างอัตโนมัติ** ตามคำขอเพิ่มเติม ฟอนต์ TH Sarabun New Bold, Auto leading 120%, Tracking 0, Metrics, Sharp, Scale 100%, Baseline 0 เหมือนเดิม และยังเป็น Text layer ที่แก้ได้ใน Photoshop
- มาสก์ตรวจขอบสีและเส้นที่ไม่ปิด ป้องกันการเข้าใจตัวอักษรเป็นบับเบิ้ล เผื่อเงา/ขอบเรืองตามความสูงตัวอักษร รอยหลงเหลือแต่ละกลุ่มไม่ถูกเชื่อมเป็นพื้นที่ลบก้อนใหญ่
- พื้นไล่สีเลือกแบบจำลองเรียบที่เหมาะสม ตรวจด้วยจุดตัวอย่างที่แยกไว้ และปฏิเสธการประมาณสีนอกพื้นที่ตัวอย่าง/สีที่เลยช่วงพื้นเดิม เมื่อไม่ผ่านจะใช้ LaMa หากพร้อม ไม่บังคับ Telea
- สร้างมาสก์ใหม่จากภาพต้นฉบับ การคลีนกรอบเดิมใหม่จะแทนผลเก่าของกรอบนั้น และใช้ Undo ได้ ผลเดิมยังอยู่จนกว่าจะมีผลใหม่ ไม่เขียนทับภาพต้นฉบับ

### ใช้กับโปรเจกต์เดิมอย่างไร

1. เปิดโปรเจกต์เดิมที่ยังอ้างถึงภาพต้นฉบับก่อนคลีน ไม่ใช่ PNG ที่คลีนเลอะแล้ว
2. กด **สร้าง Mask ทุกหน้า** ใหม่ แล้วเปิด **ดู Mask** ตรวจพื้นที่ โดยเฉพาะขอบบาง บับเบิ้ลติดกัน และข้อความมีเงา
3. กด **Clean ทุกหน้า** ตรวจผลและรายการต้องตรวจเพิ่ม
4. เปิด **เพิ่ม Text / รับคำแปล** แล้วกด **จัด Text จากคำแปลที่มีในโปรแกรม** (ไม่ต้องแปลใหม่) เพื่อใช้ขนาด/สี/ศูนย์กลางแบบ 3.1
5. ส่งออก PSD ใหม่ ได้เฉพาะ `.psd` ประกอบด้วย Background เดิม + CLEAN ภาพเต็มหน้า 1 ชั้น + Text ที่ยังแก้ไขได้

การเปิดโปรเจกต์เก่าอย่างเดียวไม่ได้สร้างมาสก์หรือจัด Text ใหม่อัตโนมัติ มาสก์เดิมที่แก้ด้วยมือยังเปิดได้ แต่ถ้ากำลังแก้งานคลีนเลอะจาก 3.0 ควรสร้างใหม่ตามขั้นตอนข้างบน

ศึกษาการปรับสัดส่วนพื้นที่และวัดข้อความจาก [Lumina](https://github.com/lumina-tl/lumina) ที่ commit `bfbf042aff4c18290198f65c18f31430cd3f5a06` พร้อมตรวจ MIT license แล้ว ดูรายละเอียดสิ่งที่นำมาปรับ/ไม่ได้ใช้และใบอนุญาตใน `third_party/lumina/` ไม่ได้ติดตั้งหรือนำโมเดลของ Lumina มารวม และยังใช้ระบบ OCR/LaMa เดิม

ข้อจำกัด: ขอบเปิด/บับเบิ้ลติดกันและพื้นลวดลายอาจยังต้องแก้มาสก์หรือขยับ Text เอง ผลที่ต้องตรวจเพิ่มไม่ถูกนับเป็นผ่านคุณภาพแน่นอน การทดสอบกับภาพที่ผู้ใช้ให้ไม่ได้รับประกันทุกหน้า

## คู่มือฟีเจอร์เดิม (เริ่มใน 3.0)

## หน้าจอใหม่ตามขั้นตอนใช้งาน

- ซ้ายบน: เพิ่มภาพ → เพิ่มโฟลเดอร์ → เปิดโปรเจกต์
- ขวาบน: OCR ทุกหน้า → สร้าง Mask ทุกหน้า (อ่านคำซ้ำ + สร้างมาสก์) → Clean ทุกหน้า (คลีนมาสก์ทั้งหมด)
- ใต้ปุ่มเปิดงาน: OCR → ภาษา; ปุ่มหยุดอยู่ข้างกัน
- ขวา: เพิ่ม Text / รับคำแปล → ส่งออกเป็น PSD
- ภาพขนาดใหญ่ทางซ้าย เปลี่ยนหน้าซ้ายล่าง; ตรงกลาง: ลากเพิ่มกรอบ → ดู Mask → ดูผล Clean และดู Text/ซูม
- ขวา: เมนูตรวจและแก้ OCR เดิมครบ รวม/แยก/ลบ/ย้ายลำดับ/ย้อนกลับ ต้นฉบับ คำแปล ตรวจแล้ว อ่านซ้ำ Google RapidOCR และผลอ่านทางเลือก จอเล็กเลื่อนส่วนแก้ไขได้
- ล่างสุด: สถานะ แถบความคืบหน้าแบบช่องพิกเซลพร้อมเปอร์เซ็นต์จากงานจริง และ Log ล่าสุด (เลื่อน Log ด้วยล้อเมาส์ได้)
- **เมนูเพิ่มเติม** ตรงกลาง: บันทึกโปรเจกต์ (หรือ Ctrl+S), CLEAN/แก้มาสก์รายกรอบ, ตรวจ LaMa, เลือก Google JSON และคำสั่งส่งออกข้อความเดิม

ธีมล่าสุดใช้พื้นดำ `#06090c` แผงเข้ม `#0b1218` เขียวนีออน `#98e55b` และม่วง `#aa83f3` ตามภาพอ้างอิงวิดีโอเกมที่ผู้ใช้เลือกแทนธีมม่วงเดิม มีกรอบมุมพิกเซล หัวใจตกแต่ง ปุ่มไฮไลต์เมื่อชี้เมาส์ และแถบโหลดแบ่งช่อง ตำแหน่งและคำสั่งยังเหมือนผังที่ขอ

ตัวหนังสือขาว ใช้ MN Khop Khun สำหรับ UI ซึ่งพบติดตั้งแล้วในเครื่องนี้ ใช้ขนาดตัวอักษรตามพิกเซลเพื่อลดการล้นเมื่อ Windows เปลี่ยน DPI เครื่องอื่นที่ไม่มีฟอนต์นี้จะแจ้งใน Log และใช้ Segoe UI ชั่วคราว ไม่รวมไฟล์ฟอนต์ไว้ใน ZIP **ฟอนต์ข้อความการ์ตูน/PSD ยังเป็น TH Sarabun New Bold** ตามเดิม ดูหน้าจอจริงใน `examples/v3_0/UI_game.png`

เปิดหน้าต่างเริ่มต้นขนาด 1880×990 บนจอ 1920×1080 เพื่อเหลือพื้นที่ขอบหน้าต่างและแถบงาน พื้นที่ภาพกว้างประมาณ 982 px เมนูแก้ OCR อยู่ทางขวาแทนคอลัมน์แสดงผลส่งออกเดิม การเปลี่ยน UI ไม่เปลี่ยนการทำ OCR/CLEAN/PSD หรือการนำเข้าคำแปลแบบยืดหยุ่น

## เปิดใช้รุ่นปัจจุบัน

ไฟล์ในโฟลเดอร์นี้อัปเดตครบแล้ว ปิดโปรแกรมเดิมแล้วเปิด **`START_3_1.bat`** หากอัปเดตในโฟลเดอร์เดิม ต้องวางไฟล์ทั้งชุด รวม `app_ui.py` สำหรับหน้าจอใหม่, `text_layout.py`, `windows_text.py`, `text_editor.py`, `photoshop_export.py` และ `photoshop_export.jsx` แล้วรัน `install_text_psd_windows.bat` หนึ่งครั้ง เก็บ `.venv` และภาพต้นฉบับเดิมไว้ หากย้ายโฟลเดอร์/เครื่อง ให้ติดตั้ง environment ใหม่ตามหัวข้อถัดไป

### ย้ายโปรแกรมไปไดรฟ์ D

ตัวโปรแกรมและไฟล์ BAT ใช้ตำแหน่งโฟลเดอร์ที่เปิด จึงรองรับการวางบน D แต่ `.venv` เป็นชุด Python ที่อาจมีเส้นทางเดิมฝังอยู่ ไม่ควรรับประกันว่าจะคัดลอกแล้วใช้ได้ทุกส่วน

1. ปิดโปรแกรม แตก `ManhwaOCR_Editor_v3_1.zip` ลงโฟลเดอร์ใหม่ เช่น `D:\ManhwaOCR_Editor` และเก็บชุดเดิมไว้ก่อน
2. รัน `install_windows.bat` ในโฟลเดอร์ใหม่เพื่อสร้าง `.venv` ใหม่ หากคัดลอกทั้งโฟลเดอร์มาแล้ว ให้เปลี่ยนชื่อ `.venv` ที่คัดลอกมาเป็น `.venv_old` ก่อน เพราะตัวติดตั้งจะไม่สร้างใหม่เมื่อพบ Python เดิม
3. ติดตั้งตัวเลือกที่ใช้อยู่ด้วย `install_rapid_windows.bat`, `install_advanced_windows.bat` และ `install_clean_lama_windows.bat` ตามที่ต้องการ แล้วเปิด `START_3_1.bat`
4. เปิดโปรเจกต์และลอง OCR/CLEAN/PSD ก่อนลบชุดเดิม ถ้าย้ายภาพต้นฉบับด้วยและโปรแกรมหาไม่พบ ให้เลือกโฟลเดอร์ภาพใหม่เมื่อโปรแกรมถาม

บนเครื่องเดิม ฟอนต์และ Photoshop ที่ติดตั้งไว้ยังใช้ได้ ข้อมูลแคช/log/โมเดลที่เก็บใน `%LOCALAPPDATA%\ManhwaOCREditor` ยังคงอยู่ตำแหน่งเดิมบน C การย้ายโฟลเดอร์โปรแกรมไม่ได้ย้ายข้อมูลส่วนนี้ด้วย ยังไม่ได้ทดสอบย้ายชุดติดตั้งจริงไป D ในการอัปเดตนี้

อ้างอิง: [Python — virtual environments ไม่ควรย้ายหรือคัดลอกแทนการสร้างใหม่](https://docs.python.org/3/library/venv.html#how-venvs-work)

เครื่องที่ใช้พัฒนารอบนี้มี TH Sarabun New Bold และ Photoshop Desktop 2026 อยู่แล้ว และติดตั้งแพ็กเกจจัดข้อความเพิ่มให้แล้ว ไม่ได้เปลี่ยนโมเดล/การตั้งค่าความเร็ว OCR

**ข้อกำหนด:** การจัดวางและดู Text ใช้ Windows, TH Sarabun New Bold, fontTools และ PyThaiNLP การส่งออก PSD ใช้ **Photoshop Desktop ที่ติดตั้งและใช้งานได้ในเครื่อง** ผ่านระบบ scripting ของ Adobe เพื่อให้ได้ Type layer ของ Photoshop จริง ไม่ต้องมี Photoshop เพื่อ OCR/CLEAN/นำคำแปลเข้าหรือดู Text แต่ต้องมีเมื่อต้องการสร้าง PSD

ไม่ได้รวมไฟล์ฟอนต์หรือ Photoshop ไว้ใน ZIP หากเพิ่งติดตั้งฟอนต์ ให้เปิดโปรแกรมและ Photoshop ใหม่ หากฟอนต์ไม่มี โปรแกรมแจ้งเหตุผล ไม่เปลี่ยนไปใช้ฟอนต์อื่นหรือข้อความภาพแทน

## ขั้นตอนแปล → เพิ่ม Text → PSD

1. เปิดภาพ/OCR และตรวจกรอบคำพูดตามเดิม ทำ CLEAN แล้วตรวจผลก่อน
2. กด **เพิ่ม Text / รับคำแปล** จะมีไฟล์ส่งแปลของทุกกรอบทุกหน้า กดคัดลอกหรือบันทึก TXT แล้วนำไปแปลภายนอก
3. ให้คง `รหัส:` ไว้ แล้วเติม `คำแปลไทย:` แนะนำให้เก็บต้นฉบับเดิมไว้ด้วย จากนั้นวางคำตอบกลับในหน้าต่างนี้ หรือกด **เปิดคำแปล TXT**
4. กด **นำเข้าคำแปล + เพิ่ม Text** โปรแกรมจับคู่ตามรหัส ตัดบรรทัดไทยและจัดกลางพื้นที่ด้านในบับเบิ้ล โดยปรับขนาดให้พอดี ถ้ารหัสตรง ต้นฉบับจะต่างหรือไม่มีหัวข้อต้นฉบับก็รับได้ โดยเก็บต้นฉบับในโปรเจกต์เดิม ถ้ารหัสไม่รู้จักหรือซ้ำ จะไม่เดาจับคู่ให้
5. หากกรอกคำแปลไว้ในช่องเดิมแล้ว กด **จัด Text จากคำแปลที่มีในโปรแกรม** ได้เลย ส่วนกรอบคำแปลว่างจะยังไม่มี Text
6. เปิด **ดูผลคลีน** และ **ดู Text** เพื่อตรวจภาพ ตัวอย่างใช้การจัดอักษรไทยของ Windows ไม่ทำภาพรวมทั้งหน้ายาวใหม่ทุกครั้งที่เลื่อน
7. กด **ส่งออก PSD** → หน้านี้/ทุกหน้า → เลือกโฟลเดอร์ จะได้เฉพาะหนึ่ง PSD ต่อหน้าใน `psd_pages` ไม่สร้างไฟล์ preview/report/PNG เพิ่ม ชื่อไฟล์ซ้ำจะเพิ่มเลข ไม่เขียนทับไฟล์เก่า
8. เปิด PSD ใน Photoshop เลือกชั้น `TEXT ...` ด้วยเครื่องมือ Type เพื่อแก้คำ ขนาด สี หรือตำแหน่งต่อได้

### หากเปิด TXT แล้วนำเข้าไม่ได้

ต้องเปิดไฟล์ที่มีคำแปลเสร็จแล้ว ชื่อไฟล์จะยังเป็น `manhwa_for_translation.txt` ก็ได้ แต่หลัง `คำแปลไทย:` ต้องมีคำแปลจริง ไม่ใช่ไฟล์แม่แบบที่ยังเว้นว่าง คงรหัสและคำต้นฉบับเดิมไว้

ตัวอ่านรองรับหัวข้อตัวหนา เช่น `**รหัส:**`, รายการนำหน้าหัวข้อ, เครื่องหมาย `：` และกรอบโค้ดที่ครอบทั้งไฟล์ เมื่ออ่านไม่ผ่าน โปรแกรมบอกบรรทัดและเน้นบรรทัดนั้นให้แก้ โดยยังไม่เปลี่ยนคำแปลในโปรเจกต์ ข้อความเกริ่นก่อนรายการต้องลบออก ไม่เดารหัสหรือจับคู่ผิดกรอบให้เอง

รุ่นปรับการนำเข้าแบบยืดหยุ่นรับหัวข้อยาวที่ผิดหนึ่งตัวอักษร เช่น `คำต้นฉbับ:` และหัวข้อย่อ เช่น `ID:`, `ต้นฉบับ:`, `คำแปล:` ได้ ใช้รหัสตรงกันเป็นหลักแม้ต้นฉบับมีการแก้คำจากภายนอก รายละเอียดที่ยอมรับจะอยู่ใน Log โดยไม่ถามยืนยันซ้ำ ไม่เปลี่ยนต้นฉบับหรือแก้เนื้อหาคำแปลเอง หากไม่มีรหัส ยังต้องมีต้นฉบับที่จับคู่ได้เพียงกรอบเดียว

ตัวอย่างรูปแบบส่งแปล:

```text
รหัส: (คงรหัสที่โปรแกรมให้)
คำต้นฉบับ: Where are you going?
คำแปลไทย: คุณกำลังจะไปไหน
```

ใช้หลายบรรทัดในคำแปลได้ การจัดใหม่จะรักษาบรรทัดที่ใส่เองและตัดเพิ่มตามพื้นที่ TXT แบบเดิมที่มีเพียงคู่คำต้นฉบับ/คำแปลยังนำเข้าได้เมื่อคำต้นฉบับตรงและไม่ซ้ำ แต่แนะนำไฟล์มีรหัสเสมอเมื่อมีหลายหน้า ปุ่มส่งออก TXT เดิมยังคงรูปแบบคู่บรรทัดเดิม ไม่เพิ่มรหัสให้โดยอัตโนมัติ

## ชั้นใน PSD

```text
TEXT - Thai
  TEXT 001 - รหัสกรอบ     ← Type layer แก้ข้อความได้จริง
  TEXT 002 - รหัสกรอบ
CLEAN                     ← ภาพคลีนเต็มหน้ารวมเป็นเลเยอร์ภาพเดียว
Background                ← ภาพต้นฉบับเต็มหน้า
```

ภาพคลีนไม่ถูกแบนรวมกับ Background จึงซ่อนชั้น CLEAN เพื่อกลับไปดูภาพก่อนคลีนได้ ถ้ายังไม่ต้องการข้อความ ให้เลือกเมนู **เฉพาะ Background + CLEAN** โปรแกรมไม่เรียก Remove Tool ของ Photoshop; CLEAN ยังใช้ขั้นตอนและโมเดลเดิม ส่วน Photoshop ใช้สำหรับประกอบ/บันทึก PSD และเขียน Type layer เท่านั้น

เลเยอร์ CLEAN ใช้ภาพเดียวกับการส่งออกภาพคลีนเป็น PNG แต่ไฟล์ PNG ชั่วคราวจะถูกลบทิ้งหลังประกอบ PSD ถ้ายังไม่มีงานคลีน จะมีเฉพาะ Background และ Text ที่เตรียมไว้ ไม่มีกรุ๊ป CLEAN ว่าง

### รอบปรับการจัดวางและหน้าจอ

- กันพื้นที่รายการ/ปุ่ม **ใช้ข้อความทางเลือก** ไว้ใต้ช่อง OCR และปรับขนาดหน้าต่างหลักให้เหมาะกับหน้าจอ
- หน้าจอใหม่ย้ายการตรวจ LaMa/เลือก Google JSON ไปเมนูเพิ่มเติม ส่วน OCR/ภาษาอยู่ซ้ายบน ค่าการทำงานเดิมยังคงอยู่
- Text เว้นระยะรอบข้อความมากขึ้น จำกัดขนาดตามบับเบิ้ล ไม่ขยายคำสั้นจนเต็มกรอบ และไม่ใช้พื้นที่นอกกรอบที่เลือกในบับเบิ้ลต่อกัน
- หากตรวจได้เพียงขอบตัวอักษรเล็ก ๆ จะไม่ถือว่าเป็นขอบบับเบิ้ล ใช้พื้นที่กลางกรอบพร้อมแจ้งให้ตรวจเพิ่ม
- **งานที่จัด Text ไว้แล้วต้องจัดใหม่:** เพิ่ม Text / รับคำแปล → จัด Text จากคำแปลที่มีในโปรแกรม แล้วตรวจภาพก่อนส่งออก PSD ใหม่ ผลคลีนเดิมใช้ต่อได้
- บับเบิ้ลต่อกันควรแยกกรอบให้ตรงแต่ละส่วน หากหลายคำพูดใช้กรอบเดียวกันต้องปรับกรอบก่อน เพื่อไม่ให้จัด Text ทับกัน

## บันทึกงานและข้อจำกัด

- โปรเจกต์ใช้ JSON format 5 เก็บคำแปลและข้อมูล Text พร้อมมาสก์/ผลคลีน เปิด format 2/3/4 เดิมได้ แต่โปรแกรมรุ่นเก่าเปิด format 5 ไม่ได้
- ถ้าแก้คำแปลหรือเปลี่ยนขนาดกรอบหลังจัด Text ให้กดเพิ่ม Text เพื่อจัดใหม่ ก่อนส่งออกจะตรวจข้อมูลที่ล้าสมัย ป้องกัน PSD มีข้อความเก่าโดยไม่รู้ตัว การล้างคำแปลในช่องแก้ไขจะล้าง Text ของกรอบนั้นด้วย
- กรอบเล็กหรือข้อความยาวจนไม่พอดีที่ 8 px จะแจ้งล้มเหลวและเก็บคำแปลไว้ ไม่ตัดข้อความทิ้งหรือสร้างชั้นภาพปลอม กรอบที่หาเส้นขอบไม่ชัด/ตัวอักษรเล็กมากแจ้งให้ตรวจเพิ่ม
- ขนาดที่จัดอัตโนมัติอยู่ในช่วง 8–144 px ก่อนปรับกับ Photoshop เอกสาร PSD ใช้ 72 ppi โดยไม่เปลี่ยนจำนวนพิกเซล เพื่อให้ 1 pt ตรงกับ 1 px
- Text เป็น **point text หลายบรรทัด** ที่แก้ไขได้ มีการใส่จุดขึ้นบรรทัดจากการจัดวางไว้แล้ว หากเปลี่ยนคำใน Photoshop ให้ปรับบรรทัด/ขนาดต่อเองได้ ไม่มีการรับประกันว่าจะจัดใหม่อัตโนมัติหลังแก้ใน Photoshop
- ตัวอย่างในแอปใช้ Windows Uniscribe ส่วน PSD วาดด้วย Photoshop/Sharp รูปทรงหรือระยะบางส่วนอาจต่างเล็กน้อย ผล PSD จะถูกตรวจให้พอดีพื้นที่อีกครั้ง
- PSD จำกัดด้านละ 30,000 px หน้ายาวเกินต้องแบ่งก่อน รุ่นนี้ยังไม่ส่งออก PSB
- ระหว่างส่งออกควรปล่อย Photoshop ทำงานจนจบ หาก Photoshop ติดหน้าต่างโต้ตอบ ให้จัดการหน้าต่างนั้นก่อน การหยุดจะรอคำสั่ง Photoshop ปัจจุบันแล้วหยุดก่อนงานถัดไป
- โปรแกรมสร้าง/ปิดเฉพาะเอกสารชั่วคราวของงานส่งออก คืนค่าการแสดงหน้าต่าง/หน่วยและเอกสารที่เคยเลือก ไม่มีการบันทึกทับงานอื่นที่เปิดค้าง

ดูผลทดสอบและขอบเขตใน `TEST_REPORT.md` ตัวอย่างจริงอยู่ใน `examples/v3_0/` แหล่งอ้างอิง: [Adobe Photoshop scripting](https://helpx.adobe.com/photoshop/using/scripting.html), [Adobe CharacterStyle](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/characterstyle), [Microsoft Uniscribe](https://learn.microsoft.com/en-us/windows/win32/intl/using-uniscribe)

4. ตรวจผล โดยเฉพาะรายการ **ต้องตรวจเพิ่ม** ก่อนนำไปใช้ กรอบที่ขอบบับเบิ้ลไม่ชัดจะอยู่ในกลุ่มนี้ด้วย

| --- | --- |
| auto | ตรวจพื้นรอบมาสก์แล้วเลือก solid / gradient / LaMa; หากไม่มั่นใจว่าพื้นเรียบและไม่มี LaMa จะรายงานล้มเหลว ไม่เปลี่ยนเป็น Telea เอง |

| gradient | พื้นไล่สี ประมาณสีต่อเนื่องจากพื้นรอบคำ ต้องมีตัวอย่างพื้นเพียงพอ |

## อ่านจำนวนผลลัพธ์ให้ถูกต้อง

- **ประมวลผล X/Y:** เริ่มพยายามทำ X จาก Y กรอบ ไม่ใช่จำนวนสำเร็จ
- **สำเร็จตามการตรวจ:** ได้ผลภาพและผ่านเกณฑ์ OCR/รอยสี/ขอบที่ตรวจได้ ยังควรดูภาพก่อนใช้
- **ต้องตรวจเพิ่ม:** ได้ผลภาพแต่ยังพบคำ/รอย ตรวจ OCR ไม่ครบ พื้นซับซ้อน หรือขอบไม่ชัด แยกจากจำนวนสำเร็จ
- **ล้มเหลว:** ทำผลภาพไม่ได้ มีเหตุผลและมาสก์สำหรับแก้ต่อ ไม่เพิ่ม patch ใหม่ให้กรอบนั้น
- **ยกเลิกระหว่างทำ / ยังไม่ทำ:** แยกกรอบที่หยุดกลางคำสั่งออกจากกรอบที่ยังไม่เริ่ม
- **ได้ภาพ = สำเร็จตามการตรวจ + ต้องตรวจเพิ่ม** จึงไม่ต้องบวกจำนวนต้องตรวจเพิ่มซ้ำอีกครั้ง

ตัวเลขเดิม 102 กรอบ / ได้ภาพ 62 / ผิดพลาด 40 / ต้องตรวจเพิ่ม 42 เทียบกับการนับใหม่คือ ผ่านการตรวจเดิม 20, ต้องตรวจเพิ่ม 42, ล้มเหลว 40 แต่ไม่ได้หมายความว่าประเมินภาพเหล่านั้นใหม่แล้ว

- ตรวจอย่างเดียวโดยไม่ดาวน์โหลดได้ด้วย `install_clean_lama_windows.bat --check` หรือปุ่มในแอป
- ผลตรวจถูกเก็บไว้ใช้ซ้ำในรอบเปิดโปรแกรม ไม่โหลดใหม่ทุกกรอบ ถ้าเปลี่ยนไฟล์โมเดลจะตรวจใหม่; ปุ่มตรวจความพร้อมบังคับตรวจซ้ำได้
- พื้นที่วิเคราะห์สีเว้นจากขอบพื้นที่ปลอดภัย 5 px และมาสก์ 10 px เพื่อลดเงา/เส้นปน; ไม่ตัดพิกเซลที่มีลวดลายทิ้งเพียงเพราะสีต่างกัน ตรวจทั้งความแปรปรวนและความเหมาะสมของพื้นไล่สี
- LaMa ยังจำกัดด้านยาว crop ที่ 2048 px กรอบใหญ่กว่านี้รายงานเหตุผล ไม่ย่อภาพอย่างเงียบ ๆ

## รายงานและกู้มาสก์

CLEAN → **เปิดโฟลเดอร์รายงาน CLEAN** จะเปิด `%LOCALAPPDATA%\ManhwaOCREditor\clean_logs` แต่ละงานมีโฟลเดอร์แยก:

- `run.json`: รุ่นโปรแกรม จำนวนกรอบ และผลตรวจ LaMa ของงานนี้
- `regions.jsonl`: หนึ่งรายการต่อกรอบที่พยายามทำ ระบุหน้าภาพ รหัสกรอบ พิกัด วิธีที่เลือก ผลวิเคราะห์พื้น ผลตรวจ หรือข้อความผิดพลาดจริง
- `summary.json`: จำนวนผลแยกกลุ่ม รวมผลบางส่วนเมื่อกดหยุด
- `region-0001.json` เป็นต้น: ภาพตั้งต้นของบริเวณ มาสก์ และพื้นที่กันขอบ สำหรับกรอบล้มเหลว/ต้องตรวจเพิ่ม/ยกเลิก

มาสก์ยังเก็บในโปรเจกต์เมื่อกดบันทึก หากต้องกู้จากรายงาน ให้เปิดภาพต้นฉบับที่ตรงกัน เลือกกรอบ แล้ว CLEAN → **เปิดมาสก์จากรายงานให้กรอบที่เลือก** โปรแกรมตรวจภาพและตำแหน่งก่อนนำมาใช้ รายงานทั้งหมดอยู่ในเครื่อง ไม่มีการส่งภาพหรือข้อความออกไป การบันทึกรายงานล้มเหลวจะแจ้งใน Log และยังเก็บมาสก์ในโปรเจกต์ให้บันทึกเอง

## OCR และขอบเขตผลทดสอบ

RapidOCR เชื่อมกับ PP-OCRv5 mobile จริง โดยเลือก recognition อังกฤษหรือเกาหลีตามภาษา ใช้ ONNX CPU และไม่เรียกเพิ่มในโหมด OCR auto ค่าเริ่มต้น รูปแบบสามคอลัมน์ การแก้ข้อความ การรวม/เรียงกรอบ แคช โหมดเร็ว และรูปแบบส่งออกยังใช้ตามเดิม:

```text
คำต้นฉบับ: (ข้อความต้นฉบับ)
คำแปลไทย: (คำแปล)
```

ดูผลทดสอบปัจจุบันใน `TEST_REPORT.md` มีการทดสอบโมเดลจริงบนภาพสังเคราะห์อังกฤษ/เกาหลีและ LaMa ไม่ใช่การรับรองทุกฟอนต์ ไม่มีภาพต้นฉบับ/โปรเจกต์/log ของงาน 102 กรอบใน ZIP จึงยังทดสอบซ้ำกรอบ 101–102 ไม่ได้ ไฟล์ตัวอย่างเดิมบางภาพเป็นผลหลังคลีน ไม่ใช้แทนภาพต้นฉบับ

อ้างอิงที่ตรวจ: [RapidOCR](https://github.com/rapidai/rapidocr), [manga-cleaner](https://github.com/NeTRuNNeRGLiTCH/manga-cleaner) การแก้ครั้งนี้ไม่ได้คัดลอกโค้ดหรือเพิ่มโมเดลของ manga-cleaner และไม่ได้เปลี่ยนตัวอ่าน OCR ให้รันหลายโมเดลพร้อมกัน

## รุ่น 2.6 — ตรวจละเอียดและเก็บงานซ้ำ

**ปิดโปรแกรมเดิม วางไฟล์ทั้งหมดใน ZIP ทับโฟลเดอร์ที่มี `.venv` แล้วเปิด `START_3_1.bat`** ทั้งหน้าหลักและหน้าคลีนต้องแสดง **2.6** ตัวเปิดจะตรวจ `manhwa_ocr.py`, `bubble_cleaner.py`, `clean_editor.py` และไฟล์ใหม่ `clean_quality.py` หากรุ่นไม่ตรงหรือไฟล์ไม่ครบจะแจ้งก่อนเปิด ไม่ต้องสร้าง `.venv` ใหม่

ภาพผลเทสล่าสุดแสดงหน้าคลีนที่ยังไม่มีปุ่มอ่านซ้ำและ gradient แบบรุ่น 2.5 จึงอาจเกิดจากการวางทับไฟล์ไม่ครบ รุ่นนี้เพิ่มการตรวจส่วนประกอบเพื่อป้องกันกรณีดังกล่าว โดยไม่ได้สรุปว่าเป็นสาเหตุเดียวของรอยปื้น

ขั้นตอนยังเป็น **เลือกกรอบ → 1. อ่านคำซ้ำและสร้างมาสก์ → ตรวจสีแดง → 2. คลีน** แต่เพิ่มการเก็บงานดังนี้:

- อ่านตรวจทั้งภาพปกติและภาพขยายปรับคอนทราสต์ทุกครั้ง แม้ภาพแรกอ่านเจอบางคำแล้ว ใช้ภาษาอังกฤษ/เกาหลีตามที่เลือก ไม่เรียก Google Vision
- ค่าเริ่มต้นเปิด **ตรวจละเอียด + คลีนซ้ำสูงสุด 4 รอบ** ใช้ทั้งคลีนทีละกรอบและคลีนเป็นชุด เมื่อยังอ่านเจอคำจะขยายมาสก์และทำใหม่ พร้อมตรวจซ้ำ
- ตรวจความต่างสีที่อาจเป็นเงาหรือปื้นบนพื้นเรียบ/ไล่เฉดแยกจาก OCR รวมพื้นที่เงาที่อยู่ใกล้คำเพื่อไม่เหลือช่องว่างระหว่างรอยเดิม
- ระหว่างเก็บงาน มาสก์อาจขยายเพิ่มภายในพื้นที่กันขอบ หลังดูผลจะแสดงมาสก์สุดท้ายที่ใช้จริงทางซ้าย ทุกการคลีนใช้ภาพตั้งต้นของกรอบกับมาสก์สะสม ไม่เติมทับผลที่ผิดซ้ำไปเรื่อย ๆ
- ไม่มีการข้ามเพราะคะแนน OCR ต่ำหรือขอบปิดไม่ชัด ประมวลผลทุกกรอบที่เลือกและมีมาสก์ กรอบที่สะอาดอยู่แล้วประมวลผลแบบไม่เปลี่ยนภาพได้
- หากครบ 4 รอบแล้วยังพบคำ/รอยผิดปกติ หรือ OCR ล้มเหลว จะระบุ **ต้องตรวจเพิ่ม** ไม่อ้างว่าสะอาด กรอบที่เกิดข้อผิดพลาดจริงจะนับ **ผิดพลาด** แล้วทำกรอบถัดไป ผลที่เสร็จยังอยู่
- `auto` ไม่ใช้ Telea/inpaint แทน LaMa อย่างเงียบ ๆ แล้ว หากเป็นพื้นซับซ้อนและยังไม่มี LaMa จะแจ้งให้รัน `install_clean_lama_windows.bat` หรือเลือกวิธีเอง พื้นสีล้วนและไล่เฉดเรียบไม่ต้องมีโมเดลนี้

**ส่งออก:** CLEAN → ส่งออกภาพคลีน → เลือกโฟลเดอร์ ผลเป็น **PNG** ใน `cleaned_pages` ชื่อ `ชื่อเดิม_clean.png` ถ้าซ้ำจะเพิ่มเลข ไม่เขียนทับต้นฉบับ บันทึกโปรเจกต์จะเก็บผลคลีนและรายงานตรวจของแต่ละ patch แต่ยังต้องเก็บภาพต้นฉบับไว้

การตรวจเชิงสีใช้ได้กับพื้นเรียบที่ผ่านเกณฑ์แบบจำลองเท่านั้น ภาพมีลวดลายที่ OCR อ่านไม่เจอยังคงระบุให้ตรวจด้วยตา เกณฑ์อัตโนมัติไม่ใช่การรับรองว่าสะอาด 100% ทุกภาพ

ผลทดลองจากภาพหลังคลีนที่ผู้ใช้ส่ง อยู่ใน `examples/v2_6/page_clean.png` รอบนี้ระบุเพียงกรอบบับเบิ้ลสองกรอบ แล้วใช้โปรแกรมหา/เก็บรอยเดิมและตรวจ OCR จริง ไม่ได้ระบุมาสก์รอยปื้นด้วยมือ

## ขั้นตอนมาสก์และเครื่องมือ (ใช้ต่อในรุ่น 2.6)

### อัปเดตจากรุ่นเดิม

1. บันทึกงานและปิดโปรแกรม
2. แตก ZIP แล้วนำ **ไฟล์ทั้งหมด** ใน `ManhwaOCR_Editor_v2` วางทับโฟลเดอร์เดิม เก็บ `.venv` ไว้ ต้องมี `bubble_cleaner.py` และ `clean_editor.py` อยู่ข้าง `manhwa_ocr.py`
3. เปิด `START_3_1.bat` ชื่อหน้าต่างต้องแสดง **2.6** โหมดสีล้วนและไล่เฉดใช้แพ็กเกจเดิม
4. สำหรับพื้นมีภาพ/ลวดลาย ให้เตรียม LaMa ด้วย `install_clean_lama_windows.bat` หนึ่งครั้ง ดาวน์โหลดประมาณ 196 MiB ถ้าเตรียมไว้แล้วจากรุ่น 2.4 ไม่ต้องดาวน์โหลดซ้ำ

### ขั้นตอนหลายกรอบ: สร้างมาสก์ → ตรวจ → คลีน

1. อ่าน OCR หรือลากเพิ่มกรอบตามปกติ เลือกหลายกรอบในรายการได้ด้วย Ctrl+คลิก
2. เข้า **CLEAN / คลีน → 1. อ่านคำซ้ำ + สร้างมาสก์กรอบที่เลือก** หรือเลือกหน้านี้/ทุกหน้า
3. โปรแกรมอ่านซ้ำเฉพาะ crop ของแต่ละบับเบิ้ล รวมพิกัดเดิมกับคำที่พบเพิ่ม แล้วแสดงมาสก์สีแดงบนภาพ **ยังไม่ได้คลีนหรือแก้ภาพในขั้นนี้** สลับช่อง **ดูมาสก์** เพื่อดูพื้นข้างใต้ได้
4. หากมาสก์ตกหล่น ให้เลือกกรอบ → **แก้มาสก์ / คลีนกรอบที่เลือก** ปรับด้วยแปรงหรือสี่เหลี่ยม แล้วกด **เก็บมาสก์ไว้คลีนพร้อมกัน**
5. กด **2. คลีนมาสก์กรอบที่เลือก** หรือหน้านี้/ทุกหน้า โปรแกรมใช้มาสก์ที่ตรวจไว้จริง ไม่มีการข้ามเพราะ confidence ต่ำหรือหาเส้นขอบปิดไม่เจอ
6. ค่าเริ่มต้นเปิด **ตรวจละเอียด + คลีนซ้ำสูงสุด 4 รอบ** จะอ่านตรวจและซ่อมซ้ำเฉพาะกรอบที่คลีน ถ้ายังอ่านคำได้หรือตรวจไม่สำเร็จ จะแจ้งจำนวน **ต้องตรวจเพิ่ม** และรายละเอียดใน Log ผลคลีนที่ทำเสร็จแล้วคงอยู่
7. เปิด **ดูผลคลีน** ตรวจทุกหน้า แล้วส่งออกภาพคลีน

หากบางกรอบยังไม่มีมาสก์ โปรแกรมจะแจ้งให้สร้างก่อน ไม่เริ่มคลีนบางส่วนโดยเงียบ ๆ ถ้ามาสก์ว่างหรือเกิดข้อผิดพลาดจริง จะแจ้ง **ผิดพลาด** และเก็บมาสก์ไว้ให้แก้ ไม่รายงานว่ากรอบนั้นคลีนสำเร็จ

มาสก์ร่างเก็บเฉพาะรอบการเปิดโปรแกรมนี้ ยังไม่รวมใน JSON โปรเจกต์ ให้คลีน/ใช้ผลก่อนปิด งานคลีนที่ใช้แล้วบันทึกในโปรเจกต์ได้เหมือนเดิม การย้อนกลับหรืออ่าน OCR หน้าใหม่จะล้างมาสก์ร่างที่อาจไม่ตรงกับภาพ/กรอบแล้ว

### หน้าคลีนทีละกรอบ

- **1. อ่านคำซ้ำ + สร้างมาสก์:** อ่านในเครื่องเฉพาะบับเบิ้ล ใช้ OCR/ภาษาที่เลือกในหน้าหลัก ไม่เรียก Google และไม่แทนคำต้นฉบับหรือคำแปลที่แก้ไว้
- **มาสก์จากพิกัดเดิม:** สร้างจากพิกัดที่มีอยู่โดยไม่อ่านซ้ำ เปลี่ยนค่า **กันขอบ / เผื่อเงา** แล้วกดปุ่มนี้เพื่อสร้างใหม่ จะล้างการระบายเดิม
- **เพิ่มมาสก์ / ลบมาสก์ / สี่เหลี่ยม:** ปรับพื้นที่สีแดง ลากสี่เหลี่ยมครอบรอยปื้นที่ OCR อ่านไม่ออกได้ เส้นเขียวแสดงขอบด้านในที่อนุญาตให้แก้
- **ดูดสี:** เลือก `solid` และกำหนดสีจากพื้นสะอาดที่คลิก เหมาะกับบับเบิ้ลขาว/สีล้วน
- **2. คลีน / ดูผล:** คลีนตามมาสก์ปัจจุบัน แสดงผลด้านขวา ตรวจ OCR หลังคลีนเป็นค่าเริ่มต้น ปิดช่องนี้ได้หากต้องการตรวจภาพอย่างเดียว
- **ตรวจคำหลงเหลือ:** อ่านเฉพาะภาพผลคลีน ถ้ายังพบคำ กด **เพิ่มคำหลงเหลือลงมาสก์** แล้วคลีนใหม่
- **ใช้ผลนี้:** นำผลกลับหน้าหลัก ย้อนกลับได้ ส่วน **เก็บมาสก์ไว้คลีนพร้อมกัน** เก็บเฉพาะมาสก์โดยยังไม่ใช้ผลคลีน

การที่ OCR ไม่พบคำไม่ได้รับรองว่าไม่มีเงาหรือรอยปื้น เพราะ OCR อาจอ่านรอยเหล่านั้นไม่ออก จึงยังแสดงก่อน–หลังให้ตรวจเสมอ ถ้า OCR ซ้ำใช้ไม่ได้ โปรแกรมจะแจ้งและใช้พิกัดเดิม/ความต่างสีในกรอบเพื่อสร้างมาสก์ให้ตรวจแทน

### วิธีเติมพื้น

| วิธี | เหมาะกับอะไร |
| --- | --- |
| `solid` | พื้นขาวหรือสีล้วน ดูดสีรอบคำ/ใช้สีที่คลิกแล้วทับเฉพาะมาสก์ |
| `gradient` | พื้นไล่เฉดเรียบ เช่น สองภาพผลเทสล่าสุด ประมาณสีจากพื้นสะอาดรอบมาสก์ เพื่อลดปื้นและแนวรอยต่อที่เกิดจากการลากสีเข้ามา |
| `lama` | พื้นหลายสีที่มีภาพหรือลวดลาย ใช้โมเดล inpainting เติมเนื้อภาพ ต้องเตรียมโมเดลก่อน ด้านยาวของ crop ไม่เกิน 2048 px |
| `inpaint` | OpenCV Telea เป็นทางเลือกที่ไม่ต้องมีโมเดล แต่บริเวณกว้าง/ไล่เฉดอาจมีรอยปื้น จึงไม่ใช่ตัวแรกสำหรับพื้นไล่เฉดในรุ่นนี้ |
| `auto` | เลือก solid สำหรับสีล้วน → gradient เมื่อพื้นสะอาดเข้ากับการไล่เฉด → LaMa สำหรับพื้นซับซ้อนถ้าติดตั้งไว้ ถ้ายังไม่มี LaMa จะแจ้งให้เตรียมโมเดลหรือเลือกวิธีเอง |

มาสก์ใหม่ครอบทั้งช่วงบรรทัดและเผื่อเงา แทนการเลือกเฉพาะขอบเส้นอักษรซึ่งอาจเหลือเนื้ออักษรหนา พื้นไล่เฉดคำนวณจากสีรอบนอกที่ไม่อยู่ในมาสก์ ผลทุกโหมดถูกประกอบกลับเฉพาะมาสก์และถูกตัดด้วยพื้นที่กันขอบ พิกเซลนอกมาสก์จึงไม่เปลี่ยน

การตรวจขอบยังเป็นการประมาณ หากหาเส้นขอบปิดไม่เจอ จะใช้พื้นที่ด้านในกรอบที่เลือกและแจ้งเตือน แต่ไม่ข้ามกรอบนั้น จึงต้องดูสีแดงว่าไม่ทับเส้นขอบโค้งก่อนคลีน โดยเฉพาะกรอบที่ผู้ใช้ลากเองหรือกรอบเปิด

ศึกษาการแยก OCR-mask กับ inpainting จาก [manga-cleaner](https://github.com/NeTRuNNeRGLiTCH/manga-cleaner) ซึ่งใช้มาสก์ตรวจข้อความและ LaMa โครงการดังกล่าวเป็นแอป ไม่ใช่โมเดลเดียว รุ่นนี้ปรับโค้ดของโปรแกรมเดิมและใช้ LaMa adapter ที่มีอยู่ ไม่ได้รวมแอปหรือ weights ของ manga-cleaner เพิ่ม

LaMa ใช้หลักการ inpainting ตามมาสก์ **ไม่ใช่โมเดล Photoshop Remove Tool/Generative Fill** ผลพื้นซับซ้อนยังอาจต้องแก้มาสก์ ไม่รับรองความเหมือน Photoshop ทุกภาพ

### ภาพที่คลีนค้างไว้จากรุ่นก่อน

เปิดโปรเจกต์เดิม เลือกกรอบแล้วเข้า editor ได้เลย โปรแกรมยังเก็บพิกัดคำเดิมไว้ กดสร้างมาสก์จากพิกัดเดิมเพื่อครอบบริเวณคำและเงา แล้วเลือก `gradient` สำหรับพื้นไล่เฉด หากรอยปื้นใหญ่กว่ากรอบคำ ให้ลาก **สี่เหลี่ยม** ครอบปื้นให้หมด ก่อนคลีนใหม่

สองภาพล่าสุดที่ส่งมาเป็นภาพหลังคลีน จึงทดสอบซ่อมรอยเดิมโดยระบุบริเวณปื้นเอง ไม่ใช่การวัดความแม่น OCR จากภาพต้นฉบับก่อนคลีน ดูผล **ก่อน / มาสก์ / หลัง** ใน `examples/v2_5/`

### บันทึกและส่งออก

- **บันทึกโปรเจกต์** เก็บข้อความและงานคลีนที่ใช้แล้ว รูปแบบ JSON version 3 เปิดไฟล์ version 2 เดิมได้ ยังคงต้องเก็บภาพต้นฉบับไว้
- **CLEAN / คลีน → ส่งออกภาพคลีน → cleaned_pages** แล้วเลือกโฟลเดอร์ จะส่งออก PNG เฉพาะหน้าที่มีงานคลีนใน `cleaned_pages` ชื่อซ้ำเพิ่มเลข ไม่เขียนทับต้นฉบับหรือไฟล์เดิม
- **ล้างงานคลีนของหน้านี้** คืนภาพต้นฉบับและล้างมาสก์ร่างของหน้านั้น งานคลีนที่ล้างย้อนกลับได้
- ผลข้อความยังเป็นคู่ `คำต้นฉบับ:` / `คำแปลไทย:` ตามเดิม ยังไม่ได้วางคำแปลลงบนภาพ
- กดหยุดแล้วโปรแกรมรอคำสั่งโมเดลปัจจุบันจบ ผลคลีนกรอบที่เสร็จแล้วไม่หาย

แหล่งอ้างอิง: [OpenCV inpainting](https://docs.opencv.org/4.13.0/df/d3d/tutorial_py_inpainting.html), [LaMa](https://github.com/advimman/lama), [Simple LaMa และน้ำหนัก TorchScript](https://github.com/enesmsahin/simple-lama-inpainting)

## RapidOCR (เพิ่มในรุ่น 2.3)

เพิ่มเป็นตัวเลือกเสริมสำหรับตรวจคำที่สงสัย เช่น UGH / LGH โดยไม่เพิ่มงานให้โหมด auto เดิม

### ติดตั้ง RapidOCR เพิ่มหลังอัปเดต

1. บันทึกงานและปิดโปรแกรม
2. นำไฟล์ภายในโฟลเดอร์ `ManhwaOCR_Editor_v2` จาก ZIP ใหม่ไปวางทับโฟลเดอร์เดิมที่มี `START_3_1.bat` และ `.venv` เก็บ `.venv` เดิมไว้
3. เปิด `install_rapid_windows.bat` หนึ่งครั้ง ตัวติดตั้งจะเพิ่ม RapidOCR/ONNX Runtime และเตรียมโมเดลอังกฤษ/เกาหลี ครั้งแรกต้องใช้อินเทอร์เน็ต
4. เปิด `START_3_1.bat` ชื่อหน้าต่างต้องแสดง **2.6**

หากยังไม่ติดตั้ง RapidOCR โหมดเดิมยังเปิดใช้ได้ ปุ่ม RapidOCR จะแจ้งชื่อไฟล์ติดตั้งที่ต้องรัน

### ใช้งานโดยคงวิธีสแกนเดิม

- สแกนด้วย `auto` / `easy` / `paddle` ตามเดิม เลือก `en` สำหรับอังกฤษล้วน หรือ `ko+en` สำหรับเกาหลี/สองภาษา
- คลิกกรอบที่สงสัย → **RapidOCR กรอบนี้** → เลือกผลใน **ผลอ่านทางเลือก** → **ใช้ข้อความทางเลือก**
- โปรแกรมอ่านเฉพาะ crop ต้นฉบับและ crop ปรับ contrast ของกรอบนั้น ไม่โหลดโมเดลหาบับเบิ้ลใหม่สำหรับปุ่มนี้
- คำต้นฉบับที่มีอยู่และคำแปลเดิมจะไม่ถูกแทนที่จนกดใช้ผลทางเลือก กรอบว่างอาจเติมผลอ่านแรกเหมือนปุ่มอ่านซ้ำเดิม
- ไม่มีการใช้กฎแทน LGH เป็น UGH เพราะ LGH อาจเป็นข้อความจริง
- ผลที่เหมือนคำเดิมจะไม่เพิ่มซ้ำในรายการ แคชแยกโมเดลและภาษา

หากต้องการทดลอง RapidOCR เป็นตัวหลัก เลือก **OCR: rapid** แล้วใช้ **โหมดเร็ว + เฉพาะบับเบิ้ล** ตามเดิม ตัวเลือกนี้อ่านแทนโมเดลหลัก ไม่ได้เพิ่ม OCR ตัวที่สองทุกกรอบ ปุ่ม OCR ใหม่ยังมีผลแทนข้อความ/คำแปลทั้งหน้าตามคำเตือนเดิม จึงควรบันทึกโปรเจกต์ก่อนทดลอง

RapidOCR ในชุดนี้ใช้ **CPU** แม้เลือกช่อง GPU เพราะชุดเสริมติดตั้ง ONNX Runtime รุ่น CPU รองรับอังกฤษและเกาหลีด้วย **PP-OCRv5 mobile** ที่ระบุชัดเจน ไม่ใช้ค่าเริ่มต้นที่อาจเปลี่ยนเมื่ออัปเดตแพ็กเกจ โมเดลเก็บใน `%LOCALAPPDATA%\ManhwaOCREditor\rapid_models` หลังเตรียมครบแล้วอ่านภาพในเครื่อง ไม่ส่งรูปไปบริการภายนอก และไม่เรียก Google เพิ่ม

RapidOCR ใช้โมเดลที่แปลงมาจาก PaddleOCR จึงไม่ใช่หลักฐานว่าแม่นกว่า PaddleOCR เดิมโดยอัตโนมัติ การลองอีกตัวอาจช่วยบางกรอบ แต่ยังต้องตรวจภาพ ผลทดสอบคำสั้นเป็นภาพสังเคราะห์ ไม่ใช่กรอบ UGH ต้นฉบับที่ผู้ใช้รายงาน

แหล่งข้อมูล: [RapidOCR](https://github.com/RapidAI/RapidOCR), [รายการโมเดล](https://rapidai.github.io/RapidOCRDocs/main/model_list/), [พารามิเตอร์](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/parameters/)

## การตั้งค่า OCR ที่เน้นความเร็ว

หลังอัปเดตไฟล์ทั้งหมดตามขั้นตอนด้านบน ให้เปิด **โหมดเร็ว**, **เฉพาะบับเบิ้ล**, **โมเดลกรอบการ์ตูน** และปิด **อ่านจุดไม่มั่นใจซ้ำ** (ค่าเริ่มต้น) ภาษาอังกฤษล้วนใช้ `en` เกาหลีหรือสองภาษาใช้ `ko+en` เริ่มลอง OCR หน้านี้หนึ่งหน้าก่อน

โหมดเร็วใช้ EasyOCR greedy ไม่ลองหมุนเพิ่ม 90/180/270 องศาทุกกรอบ และไม่ขยายภาพทั้งช่วงก่อนอ่าน ข้อความเอียง/ตัวเล็กอาจอ่านได้ด้อยกว่าโหมดละเอียด ให้เลือกกรอบที่ผิดแล้วกด **อ่านกรอบนี้ซ้ำในเครื่อง** เพื่อเรียกวิธีละเอียดเฉพาะจุด ปุ่มนี้ยังลองโมเดลสำรองและภาพปรับ contrast จึงอาจใช้เวลามากกว่า OCR ปกติ

รุ่น 2.2 โหลด OCR หลักเพียงตัวเดียวก่อน โมเดลสำรองโหลดเมื่อเกิดข้อผิดพลาดหรือกดอ่านกรอบซ้ำ แคชเก็บทั้งตำแหน่งบับเบิ้ลและคำที่อ่านได้ ควบคุม CPU threads ของโมเดล PyTorch ไม่เกิน 4 เพื่อลดการแย่งทรัพยากร

แถบล่างแสดงขั้นตอน จำนวนช่วง/กรอบ ความคืบหน้า เวลารวม และเวลาของขั้นตอนปัจจุบัน ตัวจับเวลาที่เดินแสดงว่า UI ยังตอบสนอง แต่ไม่ได้ยืนยันว่าโมเดลไม่ค้าง ผลข้อความทยอยปรากฏทีละบับเบิ้ล ไม่ต้องรอทั้งหน้า เมื่อสำเร็จจะเขียน **เสร็จแล้ว** หากหยุดหรือเกิดข้อผิดพลาดจะแสดงสถานะนั้นโดยไม่ทับด้วยข้อความสำเร็จ

การตรวจบับเบิ้ลอาจพลาดกรอบเปิด กรอบสีเข้ม หรือคำบรรยายที่ไม่มีกรอบ หากไม่พบบับเบิ้ล โปรแกรมจะไม่แอบอ่านทั้งหน้า ให้ลากเพิ่มกรอบเอง หรือปิด **เฉพาะบับเบิ้ล** แล้วสแกนใหม่ โมเดลไม่ได้ฝึกใหม่จากภาพอ้างอิงทั้งสองหน้า และยังไม่มีตัวเลขเปรียบเทียบความเร็วบนเครื่อง Windows ของผู้ใช้

อ้างอิงพารามิเตอร์: [EasyOCR API](https://www.jaided.ai/easyocr/documentation/)

## เริ่มใช้บน Windows

1. ติดตั้ง **Python 3.11 รุ่น 64-bit** พร้อม Python Launcher จาก [Python](https://www.python.org/downloads/windows/)
2. แตก ZIP ทั้งหมดลงโฟลเดอร์ เช่น `D:\ManhwaOCR` แล้วเปิด `install_windows.bat`
3. ถ้าต้องการ OCR สองระบบและโมเดลกรอบการ์ตูน ให้เปิด `install_advanced_windows.bat` ต่อ
4. เปิด `START_3_1.bat`
5. กด **เพิ่มภาพ** หรือ **เพิ่มโฟลเดอร์** → เลือกภาษา `ko+en` → กด **OCR หน้านี้**

ชุดพื้นฐานใช้ EasyOCR ได้ใน CPU ไม่ต้องมี Google key หากยังไม่ติดตั้งชุดเสริม ให้เลือก `easy` และเอาเครื่องหมายหน้า “โมเดลกรอบการ์ตูน” ออก
ชุดเสริมแนะนำ `auto` เปิด “โหมดเร็ว”, “เฉพาะบับเบิ้ล”, “โมเดลกรอบการ์ตูน” และปิด “อ่านจุดไม่มั่นใจซ้ำ” หากเป็นภาพภาษาอังกฤษล้วน เลือก `en`

ต้องต่ออินเทอร์เน็ตตอนติดตั้งและดาวน์โหลดน้ำหนักโมเดลครั้งแรก หลังดาวน์โหลดครบแล้ว OCR ในเครื่องไม่ต้องส่งภาพไปบริการคลาวด์ ตัวติดตั้งชุดเสริมดาวน์โหลดน้ำหนัก PaddleOCR จากเซิร์ฟเวอร์ทางการไว้ใน `%LOCALAPPDATA%\ManhwaOCREditor\paddle_models` ด้วย สามารถดาวน์โหลดซ้ำโดยรัน `python download_paddle_models.py` ได้ โมเดลกรอบมีน้ำหนักประมาณ 172 MB ส่วนแพ็กเกจรวม PyTorch/Paddle อาจใช้พื้นที่หลาย GB

ไฟล์ BAT จะสร้าง `.venv` ภายในโฟลเดอร์โปรแกรม ห้ามลบหรือย้ายเฉพาะไฟล์ข้างใน `.venv` หากย้ายแล้วเปิดไม่ได้ ให้สร้าง environment ใหม่ด้วยตัวติดตั้ง

ติดตั้งเองบน Python 3.11/3.12 ได้ดังนี้:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\python -m pip install -r requirements_advanced.txt
.venv\Scripts\python manhwa_ocr.py
# macOS / Linux:
.venv/bin/python -m pip install -r requirements_advanced.txt
.venv/bin/python manhwa_ocr.py
```

Linux ต้องมี Tkinter/Tk ของ Python ด้วย ส่วน GPU เป็นตัวเลือกและต้องติดตั้ง PyTorch/Paddle รุ่นที่ตรงกับ CUDA ของเครื่องเอง ค่าเริ่มต้น CPU

## หน้าจอและการตรวจแก้

- **ซ้าย:** ภาพต้นฉบับ ซูม เลื่อนภาพยาว คลิกกรอบเพื่อเลือกข้อความ หรือเปิด “ลากเพิ่มกรอบ” แล้วลากครอบคำที่ตกหล่น
- **กลาง:** รายการกรอบ ข้อความต้นฉบับที่แก้ได้ ช่องคำแปลไทย และผลอ่านทางเลือกจากโมเดล/ภาพปรับความคมชัด
- **ขวา:** ตัวอย่างผลส่งออกทุกหน้า อัปเดตตามข้อความที่แก้

กรอบสีส้มยังไม่ได้ตรวจ สีเขียวตรวจแล้ว สีฟ้าคือกรอบที่เลือก
คะแนนความมั่นใจเป็นคะแนนของ OCR ไม่ใช่เปอร์เซ็นต์ความถูกต้องที่วัดกับการ์ตูนของคุณ

กด Ctrl แล้วเลือกหลายแถวเพื่อ **รวมที่เลือก** ใช้ **↑/↓** จัดลำดับคำพูดภายในหน้า
หากต้องการแยกกรอบ ให้ใส่ Enter ในข้อความต้นฉบับแล้วกด **แยกบรรทัด** ถ้ามีคำแปลแล้ว ให้แยกคำแปลด้วยจำนวนบรรทัดเท่ากัน
กรอบที่แยกด้วยมือใช้พิกัดภาพเดิมร่วมกัน เพราะตำแหน่งของข้อความที่พิมพ์ใหม่ยังไม่ได้ตรวจจากภาพ

กด **อ่านกรอบนี้ซ้ำในเครื่อง** เพื่อทดลองอ่าน crop ต้นฉบับและภาพขยาย/ปรับ contrast ด้วยโมเดลที่เปิดใช้
เลือกผลอ่านในรายการแล้วกด **ใช้ข้อความทางเลือก** ข้อความเดิมจะเก็บเป็นทางเลือกให้ย้อนกลับ
ถ้ากรอบยังไม่มีข้อความ จะใส่ผลอ่านแรกที่พบให้ตรวจแก้

ใช้ **ย้อนกลับ** สำหรับการเพิ่ม/ลบ/รวม/แยก/ย้าย/อ่านใหม่ และ Ctrl+Z ในช่องข้อความสำหรับการพิมพ์
ระหว่าง OCR สามารถสลับดูหน้าได้ แต่ล็อกการแก้ข้อความเพื่อไม่ให้ผลที่กำลังประมวลผลเขียนทับงานที่พิมพ์
ปุ่ม **หยุด** หยุดหลังคำสั่งโมเดลที่กำลังทำงานจบ ไม่ได้ตัดการโหลดโมเดลกลางคัน รุ่น 2.2 เก็บผลกรอบที่อ่านเสร็จในหน้าปัจจุบันไว้ด้วย และระบุว่าหน้านั้นยังอ่านไม่ครบ สามารถบันทึกโปรเจกต์หลังหยุดได้

## โมเดลและการค้นคว้า

ตรวจเอกสารต้นทางวันที่ 21 กันยายน 2026 และอัปเดตโปรแกรมวันที่ 1 ตุลาคม 2026 ไม่มีการคัดลอกซอร์สทั้งแอปจากโครงการอื่น

| โครงการ | ใช้ทำอะไรในรุ่นนี้ |
| --- | --- |
| [EasyOCR](https://github.com/JaidedAI/EasyOCR) | OCR พื้นฐาน ใช้ `ko+en` หรือ `en`, CRAFT detector และ recognition; อ่าน crop หลายทิศและลอง contrast |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | OCR ตัวเลือกเสริม; รุ่น 3 ใช้ PP-OCRv5 และโมเดล recognition เกาหลี/อังกฤษ; มี adapter สำหรับผลรุ่น 2 ด้วย |
| [Comic Translate](https://github.com/ogkalu2/comic-translate) | ศึกษาสถาปัตยกรรมแยกกรอบกับ OCR ไม่ได้ติดตั้งทั้งแอปแทนโปรแกรมเดิม |
| [Comic text and bubble detector](https://huggingface.co/ogkalu/comic-text-and-bubble-detector) | เชื่อม RT-DETR-v2 ของ ogkalu สำหรับกรอบคำพูด ข้อความในกรอบ และข้อความนอกกรอบ |
| [manga-ocr](https://github.com/kha-white/manga-ocr) | ตรวจแล้วเป็น OCR เน้นภาษาญี่ปุ่น จึงไม่ใส่เป็นโมเดลหลักสำหรับงานเกาหลี/อังกฤษ |

เอกสารเพิ่มเติม: [PaddleOCR API](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html), [RT-DETR-v2 API](https://huggingface.co/docs/transformers/model_doc/rt_detr_v2)

โหมด `auto` ภาษา `ko+en` ใช้ EasyOCR เป็นหลักและ PaddleOCR เป็นตัวช่วย ส่วนภาษา `en` ใช้ PaddleOCR ก่อนแล้วจึง EasyOCR ถ้าโมเดลหลักเกิดข้อผิดพลาดระหว่างอ่าน จะลองโมเดลในเครื่องตัวถัดไป หากโมเดลสำหรับอ่าน crop ซ้ำล้มเหลว จะเก็บข้อความหลักที่อ่านได้ไว้
ค่าเริ่มต้นรุ่น 2.2 ตรวจหาบับเบิ้ลเป็นช่วงยาว 1,800 px ซ้อนกัน 260 px ก่อน แล้วอ่านเฉพาะ crop ของบับเบิ้ล ตัดกรอบซ้ำตรงรอยต่อ ไม่ส่งบริเวณ text_free หรือเสียงเอฟเฟกต์แยกไป OCR หากปิด “เฉพาะบับเบิ้ล” จึงอ่านภาพทั้งหน้าเป็นช่วง
จุดที่คะแนนต่ำกว่า 0.90 จะลองอ่าน crop ซ้ำถ้าเปิดตัวเลือกไว้ เก็บข้อความต่างกันเป็นทางเลือก ไม่ใช้คะแนนข้ามโมเดลตัดสินแทนคน

โมเดลกรอบการ์ตูนเป็นตัวเลือกเสริม ถ้าโหลดไม่ได้จะรายงานใน Log และใช้ OpenCV หาเฉพาะกรอบพื้นสว่างที่ปิดล้อม กับการจัดกลุ่มตามตำแหน่งบรรทัดแทน
วิธีสำรองนี้เป็น heuristic ไม่ใช่โมเดลที่ฝึกกับการ์ตูน และอาจพลาดกรอบสีเข้ม กรอบเปิด หรือฉากซับซ้อน
หากโมเดลตรวจพบข้อความแต่ OCR ยังอ่านไม่ได้ จะเก็บกรอบว่างไว้ให้เห็นและแก้ต่อ

โมเดลตรวจกรอบเรียนรู้จากการ์ตูน แต่ recognition ทั้ง EasyOCR/PaddleOCR ไม่ใช่โมเดลที่เราได้ฝึกใหม่ด้วยฟอนต์ทั้งหมดของคุณ
การรวมประโยคอิงกรอบและตำแหน่ง ไม่ได้ใช้ LLM แต่ง/เติมคำที่หาย ควรตรวจชื่อเฉพาะ เว้นวรรค และเครื่องหมายกับภาพ

## Google Vision ให้น้อยที่สุด

- เส้นทาง OCR ปกติไม่เรียก Google Vision เลย แม้ OCR ในเครื่องล้มเหลว
- เรียกเฉพาะเมื่อกด **ใช้ Google เฉพาะกรอบนี้** และส่งเฉพาะ crop นั้น
- จำกัด 10 ครั้งที่พยายามเรียกต่อการเปิดโปรแกรม นับ network error ด้วย ไม่ใช่ตัวเลขค่าใช้จ่ายที่รับรองจาก Google
- มีแคชตามเนื้อภาพและภาษา กดกรอบเดิมซ้ำใช้แคชแทนการส่งใหม่ รวมถึงผลที่อ่านไม่พบข้อความ
- การขยับกรอบหรือเปลี่ยนภาพทำให้แคชเปลี่ยน อาจเกิดคำขอใหม่
- รองรับ API key และ Service Account JSON (`google-auth` อยู่ในชุดเสริม)
- ไม่บันทึก key ในโปรเจกต์/ค่า config ไม่อ่าน key เก่าจากไฟล์ config v1 อัตโนมัติ

แคชอยู่ใน `%LOCALAPPDATA%\ManhwaOCREditor\ocr_cache.sqlite3` บน Windows หรือ `~/ManhwaOCREditor/ocr_cache.sqlite3` บนระบบอื่น เก็บผล OCR ไม่เก็บ API key ลบไฟล์แคชตอนปิดโปรแกรมได้หากต้องการอ่านใหม่จริง ๆ

## ส่งออกและบันทึกงาน

ผล TXT / คัดลอก มีเฉพาะคู่บรรทัด ไม่มีชื่อไฟล์ หัวข้อ Log หรือข้อมูลคะแนน:

```text
คำต้นฉบับ: Where are you going?
คำแปลไทย: เธอจะไปไหน

คำต้นฉบับ: 오늘은 날씨가 좋아요
คำแปลไทย: วันนี้อากาศดี
```

**รุ่นนี้ดึงคำและช่วยเตรียมงานแปล ไม่แปลเป็นไทยอัตโนมัติ** ช่องคำแปลไทยจะว่างจนกว่าจะพิมพ์หรือวางคำแปล
รักษา punctuation เดิม ไม่เติมจุดท้ายประโยคเอง และไม่ลบช่องว่างระหว่างคำเกาหลีแบบโค้ด v1
กรอบที่ยังไม่มีคำต้นฉบับไม่ออก TXT ให้ตรวจกรอบว่างในรายการก่อนส่งงาน

กด **บันทึกโปรเจกต์** เป็น JSON เพื่อเก็บข้อความ คำแปล ลำดับ กรอบ ผลอ่านทางเลือก และสถานะตรวจแล้ว
โปรเจกต์อ้างพาธภาพแบบ relative เมื่อทำได้ แต่ไม่ฝังภาพไว้ข้างใน ให้เก็บภาพต้นฉบับไว้ด้วย
ถ้าภาพย้ายตำแหน่ง ตอนเปิดโปรเจกต์จะให้เลือกโฟลเดอร์เพื่อเชื่อมภาพชื่อเดียวกันใหม่ หรือเปิดเฉพาะข้อความได้
ส่งออก TXT ไม่ถือเป็นการบันทึกโปรเจกต์ และไม่มี autosave จึงควรกด Ctrl+S ระหว่างทำงาน

## ข้อจำกัดและการทดสอบ

ไม่มี OCR ที่รับรองอ่านฟอนต์เกือบทุกแบบได้โดยไม่ทดสอบกับชุดภาพจริง โดยเฉพาะตัวหนังสือบิดเบี้ยว ตัวเล็กมาก แนวตั้ง อักษรเสียงเอฟเฟกต์ และข้อความทับภาพ
ได้รัน EasyOCR, PaddleOCR และ RT-DETR-v2 ด้วย weights จริงบนภาพข้อความสังเคราะห์แล้ว ผลแต่ละกรณีอยู่ใน TEST_REPORT.md ส่วนภาพอ้างอิงสองหน้าที่ได้รับวันที่ 25 กันยายนมีขนาด 89×2048 และ 108×2048 px เล็กเกินกว่าจะใช้วัดความแม่นยำตัวอักษร จึงไม่อ้างอัตราครอบคลุมทุกฟอนต์

รายละเอียดผลทดสอบของชุดที่ส่งมอบอยู่ใน `TEST_REPORT.md`
รันทดสอบ logic ได้ด้วย:

```bash
python -m unittest discover -s tests -v
```

หากเปิดโปรแกรมแล้วเจอ `ModuleNotFoundError` ให้รันผ่าน `START_3_1.bat` และติดตั้งแพ็กเกจใน `.venv` เดียวกัน
ถ้าโมเดลโหลดไม่สำเร็จ ตรวจอินเทอร์เน็ตและ Log จากนั้นลอง `easy`, ปิด GPU และปิดโมเดลกรอบการ์ตูน
การติดตั้งชุดเสริมและดาวน์โหลด weights ต้องทดสอบบนเครื่อง Windows ของผู้ใช้ด้วย ชุดนี้ไม่ใช่ไฟล์ EXE สำเร็จรูป

## สิ่งที่แก้ในรุ่น 2.1

- ระบุชื่อโมเดลอ่านเกาหลี/อังกฤษของ PaddleOCR โดยตรง เพราะ API รุ่นใหม่อาจละเลย `lang` เมื่อระบุชื่อ detector
- ปิด oneDNN ใน PaddleOCR เพื่อหลีกเลี่ยงข้อผิดพลาด PIR ที่พบกับ Paddle 3.3.1 บนเครื่องทดสอบ
- ปิดการกลับทิศบรรทัดอัตโนมัติของ PaddleOCR เพื่อให้ภาพตั้งตรงคงทิศเดิม หากข้อความหมุน ให้ลอง EasyOCR หรือ crop ใหม่
- ปรับเกณฑ์เสนออ่านซ้ำจาก 0.80 เป็น 0.90 ไม่ใช่การรับรองความแม่นยำ 90%
- เปลี่ยน cache signature ของ PaddleOCR เพื่อไม่ใช้ผลอ่านจากการตั้งค่ารุ่นเก่า
- การตั้งค่า PaddleOCR แบบไม่กลับทิศและการสลับโมเดลเมื่อ runtime error ได้ตรวจ logic แล้ว แต่ยังไม่ได้รัน weights ใหม่ซ้ำหลังพื้นที่ทดสอบถูกล้าง ดูขอบเขตการทดสอบใน TEST_REPORT.md
